# Worker 与模型路由

## 默认优先级

| 顺序 | Worker | 何时使用 | 默认模型 |
| --- | --- | --- | --- |
| 1 | ZCode App | 电脑已解锁、Computer Use 可用；任何可自包含派发的执行工作，即使其他独立对话正在运行也可使用 | `<installer-configured-model>` |
| 2 | Claude Code CLI | 锁屏、ZCode App 无法可靠操作，或 App 额度不可用 | 模型与档位由安装者/调度者显式选择 |
| 3 | ZCode CLI | Claude CLI 不可用、额度耗尽或不适配任务 | 优先 `<installer-configured-model>`；以本机实际可用列表为准 |
| 4 | Codex 子 agent | 外部 worker 均不可用或用户要求 Codex 接力 | 模型与档位由安装者/调度者显式选择 |

ZCode App 是首选通用执行智能体，不只是编码器。凡能写成自包含 handoff 的工作，默认整体交给可用的 ZCode，包括规格/代码调查、接口盘点、计划草案、诊断与复现、实现与修复、补测试、回归、首轮静态审阅、日志提炼和证据汇总。当前 Codex 已掌握上下文、自己做更快或担心 handoff 成本，都不构成跳过 ZCode 的理由。

控制面模型的额度是共享容量：优先保留给用户意图、任务边界、权限与有限自治租约、架构/安全裁决、关键反例判断和最终验收。最终验收不可委托，但机械证据收集和候选审阅可以；控制面只亲自完成形成独立结论所需的最小原始核验，不重复 worker 已完成的全量调查。

需要实现者之外的第二视角时，仍优先在正确项目中新建干净的只读对话（任意可用 worker）。第二视角只产出候选发现，不能替代控制面的最终验收。

## ZCode 上下文与子代理

| 当前状态 | 调度动作 |
| --- | --- |
| 同一任务、上下文干净，子任务共享当前基线与事实 | 复用当前 ZCode 对话；可让 ZCode 调用子代理处理有界子任务 |
| 新任务与当前任务相互独立 | 在正确项目中新建 ZCode 对话 |
| 对话混入其他项目、任务或冲突要求 | 视为上下文污染，在正确项目中新建 ZCode 对话 |

ZCode 调用子代理时仍遵守一个 worktree 一个 writer：主 worker 写入期间，子代理只做只读调查、日志/测试结果分析或审阅；需要子代理写入时，主 worker 必须先停止写入并明确移交唯一 writer 身份。子代理只完成当前派发任务的有界部分，不能自行开始下一 Task。

## Codex 模型

- 常规执行模型：由安装者从可用模型中选择，适合有界的仓库调查、实现、测试补齐和审阅。
- 轻量微任务槽：仅当任务可单轮完成、上下文很小、无跨模块判断、无需全量回归且失败不阻塞主线时使用；额度受限即视为不可用，不重试（具体模型由安装者选择）。
- 高推理能力模型：由安装者选择，用于外部 worker 不适配时的跨模块契约、复杂恢复语义、安全或架构敏感工作。
- 不把控制面模型充当普通 worker；模型档位随风险由调度者显式选择，不用更贵模型弥补模糊提示词。

## 路由判定

- **ZCode App 中另一个 worker 正在生成**：这不是降级理由。创建或打开目标项目的独立对话即可。
- **Hook 拒绝 UI 变更**：说明另一个 Codex 正在执行短暂 UI 事务。等待其发送结束并释放，再重试；持续不可用才降级。
- **Computer Use 连接长期存在**：不代表正在操作；以 Hook 是否允许变更为准。
- **屏幕锁定**：直接跳过 ZCode App，依次尝试 Claude CLI、ZCode CLI、Codex。
- **额度选择**：优先消耗可用的 ZCode 执行额度，保护 coordinator 的连续调度与验收能力；额度数字是路由信号，不自动扩大任务权限或自治边界。
- **额度耗尽**：确认当前 worker 已停止，再选择下一项（具体备选由调度者按本机可用列表决定），不得让两个 worker 同写。
- **CLI 选择**：先运行对应 `--help` 或无副作用的状态命令，确认模型参数、认证和工作目录语义，不凭记忆造参数。
